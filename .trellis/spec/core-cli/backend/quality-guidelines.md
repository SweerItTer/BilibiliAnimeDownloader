# CLI and native delivery contracts

## 1. Scope / Trigger

Applies to `core-cli`, pinned FFmpeg source builds, separate matched Rust SDKs and generated CLI packages. CLI is syntax/presentation/runtime ownership only; core owns HTTP, ranking, authentication storage, plans, jobs, resume, remux, sidecars and cleanup. Do not introduce shell business rules or GUI dependencies.

## 2. Signatures

- `bili search QUERY --type all|video|bangumi|film --page N [--auth MODE]`
- `bili info INPUT [--auth MODE]`; `bili qualities INPUT [--part N] [--auth MODE]`
- `bili login qr [--remember]`; `bili login cookie [--stdin] [--remember]`; `bili login status`; `bili logout`
- `bili download INPUT... --parts all|1,3-5 --output DIR [--auth MODE] [--remember] [--quality highest|ID] [--video-repr ID] [--audio-repr ID] [--codec CODEC] [--hdr MODE] [--subtitles all|none|LANGS|track:ID,...] [--danmaku current|none] [--merge auto|manual] [--jobs N] [--connections N] [--keep-temp]`
- `bili jobs`; `bili resume [JOB-ID|--all] [--auth MODE] [--remember]`
- `bili merge JOB-ID` or `bili merge --video PATH [--audio PATH] --output PATH`
- `bili clean [JOB-ID|--abandoned] [--include-resumable] [--dry-run]`; `bili doctor`
- Globals: `--config PATH`, `--state-dir PATH`, `--json`.

The concrete source contract lives in `core-cli/src/args.rs`; core signatures/types live in `bili_core`, not a second shell domain model. `main.rs` owns one Tokio runtime and awaits `Core::shutdown` before runtime teardown.

## 3. Contracts

- `MODE`: `auto|stored|anonymous|qr|cookie-stdin|cookie-prompt`. Auto uses existing opt-in store or anonymous; it does not prompt. Stored-record errors are not anonymous fallback. New QR/Cookie input is same-process memory-only unless explicitly remembered. Standalone no-remember login is validation only.
- Core configuration is state-directory ReadWrite only for download/resume/merge/clean; other commands use ReadOnly journal inspection. Explicit authentication storage actions are separate from journal mode.
- `qualities` without --part uses the first/sole resolved part, preserving original episode/URL-selected ordinal (e.g.13 or3); an explicit --part must match that original ordinal. Never hardcode ordinal1 for EP/`?p=` inputs.
- Anonymous/diagnostic invocations configure MemoryOnly credential capability, not just an isolated HOME. Production store policy is granted only to actual auto/stored/explicit-remember/status/logout requests; storage remains Core-owned.
- Default selection is all parts, highest **actual obtainable spatial resolution**, all dialogue tracks/current danmaku, automatic library remux. CLI forwards constraints and displays selected resolution/FPS/HDR/codec; it does not rank numeric quality IDs.
- Receiver `validate_selected_media(probe, plan)` matches media type and codec for each selected representation; known positive width/height constrain video only, while specified sample-rate/channels constrain audio only. Audio0×0 metadata does not impose video dimensions on a native audio stream. Preserve negative codec/rate/channel/video-dimension tests and use saved real plan/probe data for an offline discriminator, never another download to test a receiver correction.
- `--config` reads at most 64 KiB ordinary JSON, with unknown fields rejected. Fields: `state_dir`, `output_dir`, `jobs`, `connections`, `allow_plaintext_fallback`. CLI resolves relative paths to absolute paths; core still enforces safe ownership/conflicts. No Cookie config/argv/env field exists.
- Default dirs: platform ProjectDirs `bili` local-data `state` and `downloads`; production auth uses platform private config `auth`. An explicit state dir does not implicitly relocate the account store: smoke tests isolate both HOME/platform config and state.
- `--json` uses one-line `{ "schema_version": 1, "type": "...", "data": ... }` envelopes on stdout. Types: search/info/qualities/auth/jobs/plan/job/result/cleanup/doctor/error. Progress is typed snapshots; final job result includes `exit_code`. Human progress/notices go to stderr, final results to stdout. There are no locator/headers/QR payload/secret fields.
- One top-level watch monitor renders active-job revisions throughout download/resume/merge, including bulk resolution/planning. It uses the bounded latest Core snapshot, not an extra queue/state reducer, and must expose intermediate downloaded-byte changes before terminal results. Terminal waiting does not start a second progress printer.
- First Ctrl+C requests cooperative Pause shutdown and returns 130; second forces exit 130 and requires crash recovery. The async prompt owns the terminal-mode guard and drops the pending operation before Core shutdown, restoring terminal settings on success, malformed input and cancellation. Its bounded blocking key reader never owns terminal modes; zeroizing secret ownership spans the worker-result handoff. Redirected stdin remains explicit and must be interruptible while its pipe is open without EOF.
- A Downloaded snapshot is terminal only for requested manual merge; automatic download must wait through native remux/commit. Component errors make the invocation nonzero even when video is usable. Resume-all includes completed videos with failed requested sidecars.
- Receiver `validate_sidecar_outputs(components, output_dir)` resolves every produced path inside the output boundary, rejects unsafe files and hashes actual bytes. For danmaku, parse JSONL objects/XML/ASS structure and compare raw/XML counts plus ASS omission-adjusted counts. A zero-row/zero-byte JSONL paired with valid zero-comment XML/zero-event ASS is valid; malformed rows, mismatched formats/counts or outside paths remain failures. This does not relax production transport/protobuf/access errors.
- Native source pin/configuration is `scripts/native-lock.json`; actual install `build-info.json` and generated config headers record effective closure. Source-built shared avformat/avcodec/avutil only; no programs/network/encoders/GPL/nonfree/version3. Narrow probing decoders and configure-required closure are not falsely advertised as transcoding.
- Producer and receiver native-option guards share `verify_package.has_forbidden_native_options`: recognize line-anchored positive `CONFIG_x=yes` Make assignments or `#define CONFIG_x 1`, not negated `!CONFIG_x=yes`, comments or zero defines. Mixed negative/positive input must still reject. The stdlib semantic regression runs in existing package CI; changing this parser must not weaken the other effective flags, source/version/license or platform checks.
- Normal CLI statically integrates Rust core and dynamically uses FFmpeg. Separate `rlib` and matched `dylib` SDKs live at `target/sdk/TARGET/MODE/`, with root `build-info.json`, consumer/source/notices and actual loader dependencies. No C ABI, staticlib/cdylib, stable Rust ABI or hot-unloading claim.
- Target-scope every SDK Cargo metadata query and preserve the official consumer-lock subset check. Ship actual normal-dependency proc-macro compiler DSOs with rlib/rmeta inputs; distinguish these from the runtime Core DSO and preserve Windows compiler DLLs during runtime deduplication. Diagnose missing metadata with exact compiler-artifact/host-target receipts, not a source-only fallback or ABI-flag change.
- Cargo metadata/build machine JSON and Cargo package-tree `{p}` data are UTF-8, independent of Windows ANSI defaults. Decode these subprocess streams explicitly as strict UTF-8, including license collection and copied-source consumer metadata. Owned Rust CLI/SDK probe JSON is likewise UTF-8 (`serde_json` writer/String output). Set encoding only at those producer-specific call sites; shared native-tool runners retain their locale behavior. Never use replacement/ignore decoding or a global Python locale override to mask protocol bytes. Real Windows SDK/notice/package execution is the oracle, not source-text/mock-forwarding tests.
- Windows SDKs copy `.lib` inputs only from actual `native=` build-script search paths of existing normal-reachable registry packages, confined after resolution to that same crate. Verify the `.crate` SHA against Cargo.lock and the exact regular archive-member bytes before copying into existing `native/lib`; preserve FFmpeg's separate prefix handling. Never sweep registry/system SDK/build-output directories or use this path for bundled/generated archives. Same-name different bytes are fatal; identical existing bytes may be reused. Record package/version/source/archive SHA/member/file SHA and retain full normal-dependency notices. These are permitted Cargo-provided precompiled import inputs, not claimed CI rebuilds, FFmpeg source or Microsoft redist. Keep compiler-artifact and build-script events separate at every consumer. Retain actual copied-import removal/same-hash restoration/relink evidence in task research, not a permanent version-pinned helper or SDK metadata field; dependency upgrades must not fail for a historical import-library filename. This temporary experiment does not replace the separate generic Core-DSO removal control.
- The rlib verifier must execute the shipped copied-source Cargo recipe and readonly lifecycle, recording separate source/prebuilt proofs. Expand FFMPEG/pkg-config paths from the recipient SDK root at execution, not from the producer or Cargo build-script CWD. Relocate prefix, libdir and includedir in native `.pc` files, then prove actual pkgconf output after moving the SDK without masking overrides.
- Stream the recipient source-Cargo build's stdout/stderr directly with checked nonzero failure propagation. Its output is not metadata; do not capture it solely for a success-only print that hides failed Cargo diagnostics. Windows uses an explicit system CMD executable and raw `/d /c "{recipe}"` command line: never pass the full SET-chain recipe through list2cmdline escaping or remove `/d` AutoRun disabling. Linux retains the bash argv runner; preserve the published recipe, profile and producer-environment clearing.
- The Windows shipped source recipe canonicalizes the existing relative Cargo build root at execution with `FOR %I` / `%~fI`. Use that same value for both `CARGO_TARGET_DIR` and quoted `--target-dir`; never bake in a producer absolute path or bypass only the verifier. Keep the shared root and resolved runtime lookup semantics, Linux recipe and compilation settings unchanged. Native path/throwaway-child controls establish their stated contracts, not actual SDK qualification or a unique MSVC failure cause.
- Both prebuilt SDK modes construct one relative SDK-root compiler argv, execute it with `cwd=SDK_ROOT`, then serialize that same argv into `consumer/build-command.txt`. Use separate `"-o", "bin/..."` arguments, never `-o=bin/...`; preserve Windows `dependency=bin`. Producer-only absolute argv plus an unexecuted recipient recipe is not a linkage proof.
- Linux packages use `bin/bili`, `lib/*.so*`, app RUNPATH `$ORIGIN/../lib` and libraries `$ORIGIN`; Windows dependencies are executable-adjacent with actual transitive imports/CRT and redistribution notices. Requested flags are not proof of effective RUNPATH.
- `verify_package.parse_windows_dependencies` owns DUMPBIN dependency-name extraction for package CRT collection, package receiver inspection and SDK native closure. Preserve the existing bare-name grammar and original case; callers retain their own lowercase/policy handling. Path-bearing `Dump of file ...dll` headers are not dependencies, while unknown real bare DLL names remain visible to closure rejection. Keep a semantic parser regression, not a source-text wiring assertion.
- Windows isolated receiver environments must create `USERPROFILE/AppData/Roaming` and `USERPROFILE/AppData/Local` before child startup and point `APPDATA`/`LOCALAPPDATA` at those owned directories. Environment-variable targets alone do not establish the native KnownFolder layout; process-local KnownFolder caches can preserve an earlier failure. Never restore production profile/store access or add a product fallback to repair the test harness. Package verification subprocess failures retain stdout and stderr; current call sites are local tools, diagnostics/synthetic outputs or explicitly anonymous public-media operations, never credential-bearing authentication.
- `scripts/verify_package.py::WINDOWS_SYSTEM` is the canonical exact Windows OS-DLL set reused by SDK inspection, following the existing package import pattern. Preserve the previously recognized SDK/package union (`rpcrt4.dll`, `winhttp.dll`, `dnsapi.dll` included); no local duplicate allowlist, System32 fallback/copy, unknown-DLL relaxation or broadened name/signature rule. These OS inputs predate the Windows10/11 baseline; genuine non-system imports still require actual bundled closure and full redistribution evidence.
- `scripts/collect_licenses.py --package core-cli|bili_core --target TARGET --output FRESH_DIR --rust-runtime` collects actual crate/runtime full license/NOTICE/copyright texts and provenance. Pass runtime coverage for **static and dynamic** Rust code; SPDX strings alone and absence of a std DLL are not attribution coverage. Native/CRT full texts follow actual imports; missing/unknown coverage withholds release. Corresponding native source+recipes are a matching equivalent-access asset, not necessarily duplicated inside each app archive.
- Authenticate registry license bytes against the Cargo.lock-checked `.crate` archive, not an assumed `.cargo-checksum.json` in registry `src`. Preserve actual first-party repository license terms separately. Known published omissions require narrowly pinned canonical source text and provenance, never fabricated notices.
- Actual Windows CRT closure triggers automatic pinned official source collection through `scripts/windows_redist.py`; retain original terms, complete UTF-8 derivatives and provenance. Preserve supplementary upstream suite notices unchanged without claiming every listed component ships. Optional `--runtime-license` inputs are additions, not a default CI prerequisite.
- Installed distro copyright files can provide a complete embedded GCC Runtime Library Exception alongside the full installed GPL text; preserve the entire genuine notice and provenance rather than requiring only a standalone COPYING.RUNTIME filename. Missing full terms still withhold SDK qualification.
- Corpus generation is isolated test-only source tooling under `target/corpus-build`, never linked/shipped app code. Platform-neutral generated fixtures/provenance are reused by actual Linux/Windows native tests. Two sequential FLVs must contain distinct generated content/durations and prove one combined stream set/timeline/content order, not merely file existence.
- The HDR fixture encoder is 10-bit-only x265 (`HIGH_BIT_DEPTH=ON`, `MAIN12=OFF`) with explicit conversion and strict pixel-format selection. Tests must decode input depth/color/mastering/MaxCLL before attributing a mismatch to remux.
- Automated public discovery/download/resume/repeat commands always pass `--auth anonymous`; isolated HOME does not isolate a real OS keyring. Never run default auto/stored/login-status/logout against production account storage in smoke; synthetic auth tests use an isolated mock store.
- Artifact verifiers reading durable evidence follow the exact committed `queue.json.jobs[{id,revision}]` reference to `job-<revision>.json` and validate `checkpoint_revision`; never infer commitment from glob/latest or an obsolete `job.json`. Product shells continue using the core API.
- Candidate-package online acceptance is separate from release CI and publication. When performed, use authorized public media on actual package bytes, execute a live download and record its path/media ID; report it separately. Offline checks qualify package integrity and merge, not online media behavior.

## 4. Validation & Error Matrix

| Condition | Result |
|---|---|
| Clap syntax, zero/out-of-range limits, malformed or unavailable part ordinal, mixed track/language selectors, unknown config fields | exit 2; safe invalid-input message |
| Non-TTY QR/prompt or terminal `cookie-stdin` that would echo | exit 2; explicit correct input route |
| Hidden prompt receives LF/CR Enter, malformed input or first Ctrl+C | submit normally or exit 2/130 as appropriate; no input echo; restore terminal settings before process exit |
| Login/access/challenge/unavailable/changed explicit selection | exit 3; no automatic fallback |
| Busy/read-only/store/transport/filesystem/corruption/native/remux failure | exit 4 |
| Requested sidecar failure | nonzero per component; preserve video; retry through core |
| Valid empty danmaku JSONL + valid XML/ASS with matching zero counts | receiver accepts and records actual file hashes; no invented nonempty content |
| Malformed JSONL/XML/ASS, count/omission mismatch, unsafe or outside sidecar path | receiver rejects; never bypass by component kind |
| Pause/cancel/user interruption | exit 130 |
| All requested components succeeded or verified skipped | exit 0 |

Mixed batch precedence is 130, 4, 3, 2, 0; retain each result code. Native/source/checksum/loader/license qualification failure withholds release, not fallback to ffmpeg.exe or a fictitious download link.

## 5. Good / Base / Bad Cases

- Good: non-TTY invocation explicitly reads Cookie stdin, authenticates once, resolves/plans/downloads/resumes locators in that Core lifetime, never persists without --remember.
- Base: fresh anonymous info/jobs/doctor work without an existing writable journal; normal public download reports exact selected streams.
- Bad: `login cookie` without --remember followed by a separate download is described as logged in; numeric Dolby1080 quality outranks obtainable4K; automatic wait returns success at intermediate Downloaded; package smoke passes using developer `LD_LIBRARY_PATH`.

## 6. Tests Required

Consolidated owner runs fmt/check/clippy/test **once after all edits settle**, then targeted fixes rerun only affected checks before final gates. Shell checks cover bounded real-part selection and subtitle selector ambiguity, non-TTY modes and exact CLI exit/output behavior. Core owns fault/selection/auth/sidecar/remux tests; do not duplicate its implementation tests with source-text or mock-forwarding assertions.
Actual terminal smoke checks LF and CR submission plus first-interrupt restoration using synthetic malformed input or no entered input, without remember-me. Assert all terminal attributes before the harness restores anything, no secret echo, the real exit code and no forced kill. Separately hold redirected stdin open without EOF and verify cooperative interruption; unit tests of key mapping alone are not terminal lifecycle proof.

The full CLI acceptance contract covers source build, actual independent rlib/dylib consumers/import inspection/removal proof, extracted-package help/version/doctor and native replacement, plus public allowed-media download/remux/interrupt/resume/verified skip. Public-media checks are separate authorized manual acceptance, not a release-CI/publication prerequisite; Section 8 defines the current Linux release gate. Extracted smoke removes developer native/config loader variables and isolates private state/HOME. Linux2.43 local builds do not prove glibc2.35 support; actual baseline CI/Windows execution and retrievable qualified artifacts are separate evidence. Never mark a workflow definition or upload-only artifact as clean-machine qualification.
Dynamic SDK verification records one controlled Core-DSO loss with the actual loader failure naming Core, restores the exact hash and confirms a healthy readonly run. A source-built Core dylib or an arbitrary nonzero exit is not this prebuilt-DSO proof.
Python packaging behavior checks use `python -m unittest discover -s scripts -p "test_*.py"` in the existing CI verification step. Native guards test disabled/positive/mixed configured inputs; sidecar checks use actual temporary files for valid-empty, malformed/nonmatching and outside/count-mismatch cases. Source-text/wiring pins and nonempty-only assertions are not substitutes.
SDK and package CI steps use the platform-default shell (Windows PowerShell/Linux Bash), preserving initialized MSVC discovery. Each SDK mode is a separate single-command step so the original nonzero exit is not masked by a later mode; do not introduce linker/PATH overrides or source-text wiring tests for this shell boundary.
- Local-first delivery uses the existing `build_ffmpeg.py` → Cargo CLI launch/local merge → `verify_core_linkage.py` → `package.py` → `verify_package.py` entrypoints; CI supplements local evidence and is not a prerequisite for reachable local work. Keep private pkgconf/libclang resource-dir and build loader settings child-only, document their real paths, and remove them from extracted-runtime environments. The default offline receiver does not perform manual merge: record an independent fresh-extraction merge when claiming that path, including durable completion and unchanged input/output hashes.
- Native Windows source-build proof requires an actual native Rust/MSVC/Windows SDK/libclang/MSYS toolchain; a missing prerequisite is not library incompatibility, and downloaded Windows runtime evidence is not local compilation. Install dependencies or alter global environments only with authorization. Current-host glibc 2.43 results do not qualify Ubuntu 22.04 bytes; historical symbol floors/test counts stay attached to their original artifact tuple.
- Current Linux x86_64 CLI releases are qualified by the Section 8 mandatory offline gate; this section's broader multi-platform/SDK/recovery contract must not be claimed, and untested Windows/SDK/recovery items do not block those releases.

## 7. Wrong vs Correct

Wrong: shell sorts `quality_id` and silently chooses a different stream; sets `FFMPEG_DIR` at runtime; assumes av* DLL names are complete closure; copies a full workspace into an SDK source archive.

Correct: shell forwards constraints to `Core::plan`, prints its exact keys, validates real loader imports and app-relative paths, packages corresponding native source/notices and an explicit allowlist of source/config files, and reports only exercised checks.

## 8. Release candidate and publication workflow

- Tags must equal `v` + `core-cli/Cargo.toml` version; tag commit, checked-out `HEAD`, and `GITHUB_SHA` must resolve identically and belong to the repository's current default branch. Read that branch from `github.event.repository.default_branch`, not a hardcoded branch name.
- Every `v*` tag runs the same build, independent-VM verification, and publication path. The only tag-derived difference is the GitHub prerelease/latest metadata, computed once as `"-" in version.partition("+")[0]`; `2.0.0+build-meta` stays a stable release and all `alpha`/`beta`/`rc` prereleases share the path.
- Linux x86_64 release CI uses Ubuntu 22.04 to build/package and produce a matched native probe, then independently checks the actual package on a clean VM: package/native-source checksums, dependency/native/license inspection, isolated CLI smoke, offline fixture and synthetic managed-remux smoke. The offline receipt requires `status`, `package_validation` and `offline_merge_smoke` to be `passed`, with package/source hashes and the runtime `BUILD_INFO.json` tuple; it must explicitly record `public_media_input_provided: false` and null `public_media_id`, `public_media_profile` and `authentication`. The offline receipt is not online proof.
- Publication requires successful offline qualification and validates those receipt fields, hashes, build tuple and non-placeholder versioned changelog notes. It does not require online-only discovery or `basic_smoke` results, and must not treat offline evidence as proof of online behavior. No network challenge bypass or credential fallback. A stable tag adds no platform/SDK/recovery gates.
- Public assets are a strict five-file allowlist: runtime archive, matching native-source archive, `CHANGELOG.md`, `verification.json`, `SHA256SUMS`. Probe, fixture and SDK artifacts are never release assets.
- Create an empty draft with the derived prerelease metadata, upload without clobber/skip-existing, compare exact asset names, byte-compare the downloaded `SHA256SUMS` with the expected manifest, verify the four assets it lists, then publish with the same derived metadata. Existing releases fail closed; never create tags, overwrite or auto-delete drafts.
- `cli-packages.yml` is pull-request and manual checking only: it keeps the Linux/Windows runtime, SDK and opt-in manual live checks and never publishes. Pull requests never contact Bilibili.
- Optional online acceptance is separate from release CI/publication. If explicitly authorized and the external service is available, run the existing verifier against actual package bytes and matching probe, for example: `python scripts/verify_package.py <package> --target x86_64-unknown-linux-gnu --native-source <matching-native-source> --probe-helper <matched-probe> --public-media-profile basic --public-media-id BV1gD4y1o72p --report <online-report.json>`. The verifier uses `--auth anonymous` for live info/qualities/download and reports online discovery/basic smoke separately; do not mix that report with the offline receipt. Service access is not guaranteed.
- Required workflow evidence: YAML parses with three release jobs and least-privilege write only on publisher; shell syntax parses; synthetic invalid receipt/hash cases fail. Do not claim hosted qualification until tagged workflow actually succeeds.
- Linux build jobs (media fixtures, the Linux leg of the CLI build matrix, and the tagged release candidate) run in the digest-pinned `ci-linux` image; independent smoke and release verification stay on clean hosted VMs. Update all three digest references together after a successful publish, and the Rust build steps check the image toolchain against the checkout before compiling.
- Wrong: create a public release before readback or include probe/test fixtures; correct: preserve the same verified runtime/source bytes and publish only after strict draft asset readback.
