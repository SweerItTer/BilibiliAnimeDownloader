# Native browse/download interaction

## 1. Scope / trigger

The approved native egui interaction and basic appearance polish, without a large visual redesign. Read the shared core browse/download contract and actual Rust modules; older generic GUI guidelines remain templates.

## 2. Signatures

`App` owns navigation intent, one `SearchState`, retained `DetailState` drafts, `ConfigState` and grouped `QueueState`. `backend::Operation/Outcome` is the bounded typed bridge. `Prepare` carries exact parts, explicit profile and refresh-versus-new-intent metadata; acknowledged admission returns immutable plan/job receipts. The host owns one Tokio runtime and joins background/native work on shutdown.

`isolation::DebugIsolation::from_environment(state_dir: Option<&Path>) -> Result<Option<Self>>` selects disposable debugging only when `BILI_GUI_ISOLATED_DEBUG_DIR` is set. `preferences()` and `configuration()` supply isolated storage and a normal CoreConfig to the unchanged production App/Bridge/Core startup. `GuiPrefs.storage_path: Option<PathBuf>` is process-local (`serde(skip)`), retained across appearance reset and used on every isolated save.

Optional `BILI_GUI_OFFLINE_REPLAY` supplies a local [Core response replay](../../bili_core/backend/offline-api-replay.md). It requires explicit isolation and validates before root/window creation. It does not construct shell outcomes or substitute another App/Bridge. `scripts/debug_gui.py` generates response data under ignored target output and launches the same production executable.

## 3. Contracts

The BiliDL-only logo returns home. Header categories, shorter search and right-aligned equal circular avatar/history replace the sidebar. Settings is an avatar submenu. Keep the frameless title bar compact, with drag and native window controls but no duplicate brand or slogan. Covers open details; only explicit bulk mode selects cards across pages/categories. Video owns channels/sorts; PGC has source-provided genre/section browsing separate from keyword search. Pagination is `< current/total >`; current is editable in place, Enter validates, Escape cancels, and unknown totals remain unknown.

Cover painting retains the decoded texture's intrinsic dimensions. Video cards use landscape slots and Bangumi/Film use portrait slots; contain and center the actual image without changing its aspect ratio. Keep the full slot as the card hit target. Never pass target-slot dimensions as a texture's source size. Category controls need no redundant “分类浏览” caption. Single-line fields share vertically centered normal body text and explicitly muted placeholder text; inherited global ink must not make a hint look like entered content. Text, caret and pointer selection must agree after alignment.

`GuiPrefs.appearance` persists `System`, `Light` or `Dark` independently from the existing accent ID. System follows `Context::system_theme()` and falls back to Dark when unavailable. Native theme changes invalidate the applied-appearance cache even when preferences are unchanged. Use real mode-specific egui visuals, neutral base surfaces, readable main/muted/status text and modest corners; accent presets change emphasis, not every surface. Apply each UI thread's presentation tokens before painting its context; headless contexts on different threads must not replace each other's tokens.

`theme::button_width` supplies opaque `p.ink` for disabled labels and lets egui apply its native disabled tint once. Do not pre-fade the label alpha: egui 0.29's additional tint makes that translucent input almost white on Light surfaces. Inspect disabled crop/remove controls in both visible appearances; this presentation fix must not enable those actions.

Background opacity is applied exactly once against a neutral backing selected by the resolved light/dark mode, never by the accent. `GuiPrefs.background_brightness` defaults to 100 and sanitizes finite values to 20..100, with non-finite values reset to 100. Brightness scales image RGB independently of opacity. At 100% opacity and brightness the image retains its actual source RGB; changing the accent cannot reprocess or recolor it. Unoccupied image-covered content surfaces are transparent, never a second themed veil. Header, custom title bar and content reading surfaces keep neutral mode-specific backing, so a bright or dark photo cannot erase the logo, text or window controls. For the pinned gamma-blending renderer, use a gamma-premultiplied opacity tint instead of linear-premultiplied white-alpha tint. Keep paint clipped to its configured region and crop/blur independent.

Unique/explicit resolved parts initially select themselves; whole multi-part details start empty. Detail and bulk use the same configuration model. A deliberately selected whole bulk content includes its unadmitted parts, adjustable before admission. Per-part catalogs and `QualityCatalog::select` determine actual obtainable quality choices, including previews/login/VIP restrictions. Advertising a quality alone does not make it a selectable option. Single-content preparation has one concrete selector; default to the highest actual choice without duplicate highest/common pseudo-options. Batch common choices may use the union of row intersections, but a row selector offers only its own actual choices. Retain explicit unsupported common choices as red blocking rows until override or deselect; refresh must not silently downgrade an explicit selection. Server planning revalidates all pending parts before any admission.

Retained detail drafts use `(ContentRef, ordered original PartRef identities)` as their key. A whole video and an explicit `?p=2` resolve share a content identity but have different selection scopes; restoring by ContentRef alone substitutes the whole draft and loses the requested original part. Apply the same key when restoring current results, retaining late results and saving Home navigation. Whole-video and individual-part drafts must preserve their own deliberate selections independently.

Download preparation is a centered, bounded floating dialog with space on all four sides and an internal scroll area, no redundant title/gray title bar. Episode choices wrap across the row's available width and keep their original PartRef identity when toggled; a long season must not become a narrow vertical list beside unused space. Background workspace inputs are disabled while it is open; close/Escape restore them. Advanced options start collapsed and expand in place. `GuiPrefs.default_download_rate_mib` defaults to 0/unlimited and is sanitized independently of appearance. Only a new draft copies it; reopening/refreshing a draft retains its local rate override and advanced state. Requests capture the batch rate without mutating the global default, admitted receipts or queued jobs.

Batch directory changes remain separate from opt-in default changes. Capture directory/default intent, batch rate/profile/sidecars/quality when submitting. Only acknowledged parts leave selection. Keep receipts independent from mutable retry settings and wait for admitted IDs to appear in snapshots before conflicting actions. Partial failure/cancel/reentry retains remaining intent. Refresh updates catalogs without replacing deliberately changed parts. Failed preparations/browses retry their original typed intent.

Navigation revisions distinguish awaited results from current display intent. Home/history/categories/settings/back or cancelling a read operation invalidate automatic detail/dialog opening. Late successful reads cannot reopen a dismissed workflow or replace cancelled committed results. Enqueue receipts and committed QR results survive cancellation; they do not take over navigation.

History has exactly In Progress, Failed and Completed. Paused/interrupted tasks remain resumable in In Progress; sidecar failures and NeedsAttention join Failed. Group stable source projects, filter type and sort by admission time; order original parts within projects. Completed actions reveal the actual Windows path and expose useful media/attachment parameters. Project directory choices reflect distinct actual roots. Verification, reveal and media-info operations honor foreground operation availability; a visibly enabled action must not be silently discarded by `App::send`. Confirmation re-evaluates whole-project IDs; no deletion during admission/active work. Record removal and verified-file recycling are separate; system recovery has no fake in-app Undo.

Account switching preserves drafts and affects future operations. Task-specific replacement retargets only that stopped task; adding a new QR profile uses activate=false and the explicit login_profile receipt, preserving global selection and preferences. New accounts require a fresh remember choice. Cancellation only cancels the challenge and retains the prior account. Unknown expiry/membership stays unknown; catalog obtainability is authoritative.

Only a supplied supported voucher exposes verification. Windows `verification::View` is created after explicit action, uses a temporary/incognito context and an in-memory custom protocol origin, bounded nonce-matched IPC, no downloads/new windows/permissions and no Bilibili credentials in JavaScript. About-blank IPC is unsuitable for this library's HTTP URI wrapper. The server must validate the proof before success. Drop the native controller before submitting proof or on close/cancel/timeout/shutdown. No hidden startup WebView or browser daemon.

Details use a summary beside the cover and a responsive full-width episode grid below it, with bounded independent scrolling and the count/actions above the grid. Unique or explicit parts use a compact summary-level download action. A later deliberate preparation may select a previously acknowledged part after its record is removed; cancelled partial drafts and manual deselections remain unchanged.

Foreground search/browse/resolve/preparation shows indeterminate progress and actual elapsed waiting time, including initial category conditions. Keep pending state until the matching terminal response or cancellation; suppress empty-result conclusions while waiting. Pending work disables paging (including an already-open inline editor) and bulk-mode/selection actions, preserving the captured query and selection. Submit closes the inline page editor before waiting; completion commits only the matching page. Retry belongs in core, never in the paint loop. Show only allowlisted transport stages and validated actual HTTP status, without inferred attempt counts. Errors with a retry or verification action remain until explicit dismissal or action, rather than expiring with informational notices. Cover requests use a separate bounded lane and at most two tasks; foreground work aborts/joins prior cover requests and emits `CoverDeferred`, which releases only the requested marker. Decorations cannot reserve all connections, starve foreground commands or block shutdown acknowledgement.

History consumes core aggregate byte progress, never reconstructs it from a completed resource prefix or clamps it to the largest previous value. A resume counts validated retained bytes from every resource before transfer starts. A real checkpoint invalidation or server-required replacement may decrease this value; presentation must show that actual reset rather than conceal it.

Provider quality names and actual pixel dimensions are independent. Show the known dimensions of the selectable representation alongside its source tier, only when selected parts agree; do not derive a tier from height or invent uniform dimensions for mixed parts. History plan dimensions remain distinct from actual media inspection. Preserve cropped widescreen streams without padding, scaling or silently downgrading their provider tier.

## 4. Validation / error matrix

| Condition | UI result |
| --- | --- |
| Unsupported quality/preview/rights | Red row plus cause and explicit override/deselection; Start disabled |
| Read cancelled or navigation changed | Preserve committed results/draft; no reopening |
| Partial admission | Keep actual receipts and remaining retryable parts on current workflow |
| Network / sidecar / auth failure | Corresponding checkpoint / sidecar-only / task credential action and persistent safe code |
| Pending page/bulk operation | Keep request and selection unchanged; disable conflicting input until result/cancel |
| Invalid retained bytes or full replacement response | Show core's actual reduced byte count; no cosmetic high-water clamp |
| Unknown/missing media or modified output | Honest unknown/error; offer record-only removal when appropriate |
| Missing WebView runtime or unsupported challenge | Explicit failure; retain retry intent, no fake verification |
| Isolated debug root is relative, exists, has a conflicting --state-dir, or proxy settings are incomplete | Exit 2 before preferences/Core/window startup; no fallback to production storage |
| Fresh isolated root and validated proxy settings | Normal production window with empty private state/output, private preferences and memory-only accounts; no updater worker |

## 5. Good / base / bad

Good: continue adding while acknowledged receipts remain visible and account changes refresh only relevant catalogs. Base: anonymous browsing and original saved tasks survive a normal close/reopen. Bad: stale preparation opens over Home, a retry changes old receipts, a task-only QR changes the global account, or a generic task detail replaces useful file/media actions.

## 6. Tests required

Input-driven egui tests cover header/layout, search/detail/config/admission/history flow, scroll return, inline paging and pending-input freezes, mixed strict quality, cancelled/new part intent, partial acknowledgement, late-result/cancel races, persistent actionable errors, typed retry, account isolation and QR cancellation. Appearance tests cover old preference defaults, saved explicit/system modes, actual egui light/dark visuals, text/button/status contrast, independent UI threads and neutral image opacity/brightness. Core tests own transfer/durability/credential/filesystem semantics, including resumed multi-resource byte totals and genuine resets. A separate ignored native Windows test loads only an in-memory local page to exercise actual WebView creation/IPC/destruction; it never solves a real CAPTCHA. Report executed tests and remaining live-service/platform limits separately.

Layout changes need inspection of the production GUI executable through its normal `gui/src/main.rs` entry, in a visible native window operated through screenshots and Computer Use or scripted pointer/keyboard input. Include its real App, backend bridge, frameless chrome and controls. Inspect representative portrait and landscape covers, empty and populated inputs, focus/caret, details and directory fields when available. Geometry/existence assertions alone do not establish acceptable rendering. Do not create or launch an alternate test GUI, a fixture `Review` host, an offscreen GUI renderer or a separate software rasterizer for this acceptance. The existing `app::layout_tests::native_layout_review` / `gui/src/app/native_review.rs` fixture host is excluded from further GUI debugging under the user's 2026-11-05 instruction; its historical screenshots do not qualify the production executable.

Disposable debugging uses a fresh absolute `BILI_GUI_ISOLATED_DEBUG_DIR` in the child process, with `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` each exactly `http://127.0.0.1:0`, and an explicitly empty `NO_PROXY`. Conflicting lowercase variants/bypasses are rejected. Main validates these values and rejects `--state-dir` before atomically creating a new root; existing roots fail instead of reusing any tasks. Storage is root/state, root/output and root/preferences/gui-preferences.json. Preferences never load/save the production file, force remembered-login/update flags off on isolated load/save, and preserve their private path across appearance reset. CoreConfig remains MemoryOnly and main does not create an update worker. Normal startup without the environment key is unchanged.

Ordinary production API/media reqwest builders use system proxies; auth, covers, verification and sidecars reuse these clients. The temporary proxy restriction must be verified with the same dependency versions against a reachable loopback destination: an explicit unproxied control succeeds, while both production-style clients fail before making HTTP/HTTPS destination connections. Run this probe with the exact GUI child environment before opening its window. Replay additionally makes Core itself explicitly restrict both clients, independent of inherited environment. This is an application HTTP-client restriction, not an OS firewall or network sandbox. Keep proxy settings child-local; do not change the user's system proxy or firewall. Explicit local API replay may provide synthetic metadata through the real Core parsers; missing replay entries remain errors with no live fallback. Do not fabricate shell outcomes or successful authentication, transfers or files for screenshots. `--state-dir` alone still does not isolate preferences/auth.

Nonvisual isolation regressions assert fresh empty state/output and MemoryOnly accounts, rejection before root creation for invalid proxies/relative roots/state overrides, rejection of root reuse, private preference load/save and suppression of remembered-login/update flags, and retention of that private store across App appearance reset. These tests do not create an egui frame, window or renderer.

The scoped-detail regressions drive typed bridge results and App collection without creating frames: whole versus explicit part, two different original parts and a late explicit result must retain independent drafts. Visible production-window inspection separately verifies the original part number in details, configuration, admission receipt and failed history. Synthetic replay also exercises long-season scrolling, quality mismatch blocking, permission errors, draft reopening, directory validation and minimum-window bounds. Blocked media requests must remain actual failures, never successful fixture downloads.

Retain ordinary pure input/state regressions and the separate nonvisual doctor/package/update checks, but do not use those as GUI appearance acceptance. Keep production-window inspection evidence separate from automated pass counts and from historical fixture-host evidence. Treat GUI debugging as the observed crash-triggering scenario reported by the user; the exact operation and kernel failure chain remain unresolved. A visible window and disabled networking do not by themselves establish driver stability or resolve the crash. Run one bounded visible debugging session at a time; do not overlap it with workspace builds, full test runs or another GUI test host.

## 7. Wrong versus correct

Wrong: open a modal whenever preparation completes, resolve an explicit-account batch with global credentials, or persist the whole UI mock as real job state. Correct: gate display by live intent, use `resolve_for`/catalog/planning with the captured profile, and consume durable core snapshots and acknowledgements.

Manual search review: place the bounded search field immediately after the category controls; only account/history actions align to the right edge. Use 12-point horizontal input margins and 6-point rounded reading surfaces and selected sort buttons (egui selected Button defaults to square corners). The empty discovery workspace shows centered “搜索以获取结果” without a small backing label. Offline review supports keyword “你好”, both search pages, video sorts/channels, and all six PGC sections/genre controls; synthetic data never qualifies live service behavior.

Explicitly authorized anonymous live inspection may set `BILI_GUI_ANONYMOUS_LIVE_DIR` to a fresh absolute root. Reuse private preference/state/output and MemoryOnly storage without loading production profiles or starting an updater. This mode rejects offline-root/replay variables and state overrides before creating any path; CoreConfig.api_replay remains None and normal HTTP clients use real services. `scripts/debug_gui.py --live-anonymous` generates no response file and sets no debug proxy; only normal inherited proxy settings are retained. Live requests remain limited to the user-authorized operations; access/verification challenges are reported without bypass or remembered-account fallback.

Manual download review follow-up: account menu uses full-width left-aligned rows without nested button boxes. Download configuration pins the editable output folder, folder picker and explicit set-default intent above its scroll body; opening Advanced cannot hide them. Row/common quality popups are 170 points wide and allow 320 points of list height. Remove skip state: only checked parts are submitted; empty rows do not block other selected content. Keep one accessible native-vector X close control and a history action after admission, with no duplicate close/continue action. A selected-representation native verification failure retains resources and exposes explicit revalidation/remux retry.

Regular `--profile-dir PATH` startup uses that profile's preferences/state/output and its own Remember store namespace (no plaintext fallback), rather than MemoryOnly debug startup. It is exclusive with state-dir and debug/replay environment modes. New profiles are anonymous until explicit login; a saved opt-in marker and custom output survive reopening and appearance reset. Explicit-profile updates stay disabled; private preferences contain only the opt-in marker, never credentials. Account persistence tests inspect policies and isolated preference files or use existing Core store mocks; never exercise a real login or production keyring automatically.

Visible production-window regression: a right-to-left `with_layout` inside the vertical configuration header consumes the entire available Window height and centers its X in that space. Allocate that close row with an explicit 28-point height; budget the pinned directory and scroll body afterward. Pure state tests cannot validate that the directory/list is actually visible.

An old task can reference a removed session even while the global account is logged in. For `LoginRequired` at `selected credential profile unavailable`, explain the missing task association instead of reporting an expired QR or demanding another scan. Failed account/entitlement tasks offer an explicit “使用当前账号重试（name）” action when a logged-in selected profile exists, alongside manual account selection. Capture that profile in `RetargetProfile`; its durable acknowledgement triggers Retry for that job only, preserving global selection and retained media. Never silently replace task credentials merely because global selection changes.


Accepted discovery pages request one scroll reset, consumed only by the visible results viewport. Successful paging/filter/sort changes start at the top; failed or cancelled reads keep the committed position, and returning from details preserves it.

Cover textures use an LRU capped at 64 entries and 32 MiB of decoded RGBA data. Avatar access also touches recency; eviction allows a later fetch. Offscreen slots retain geometry without requesting/painting images. Borrow result cards while painting instead of cloning their strings each frame. Child-local BILI_GUI_RENDER_DIAGNOSTICS=1 reports only public driver strings and bounded scroll CPU/frame-interval aggregates, never UI/account text, credentials or screenshots. Measure in the production native window, with no build/full tests running alongside it.
